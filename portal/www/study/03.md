# Project Title: The Multi-Department Shared Directory Infrastructure

This project simulates setting up a secure, shared server environment for an organization. You will configure users, groups, shared spaces, and advanced access restrictions to protect sensitive corporate data.

---

## Phase 1: Identity & Group Creation

* Provision Accounts: Create multiple distinct user accounts representing different roles (e.g., alice_hr, bob_dev, charlie_audit).
* Establish Departments: Create dedicated local system groups for each department (e.g., hr_dept, dev_dept).
* Manage Memberships: Assign users to their primary and secondary group slots to match their corporate roles.

## Phase 2: Environment Provisioning & Access Controls

* Profile Customization: Modify user environment profiles to auto-set custom aliases and path variables upon login.
* Sudo Matrix Enforcement: Configure selective root privileges using the /etc/sudoers file, allowing only specific users to run restricted commands without passwords.
* Inherited Group ID (SGID): Create a shared folder where any newly created file automatically inherits the department group ownership rather than the creator's group.

## Phase 3: Advanced Access Control Lists (ACLs)

* Standard Permission Mapping: Use standard Linux permissions to lock down department folders so only members can read or write files.
* Granular ACL Overrides: Apply specialized Access Control Lists to grant an outside auditor read-only access to a locked department folder without adding them to the department group.
* Default ACL Rules: Set default directory permissions so all future sub-files and sub-folders automatically receive strict, pre-defined ACL access rules.

## Phase 4: Sensitive Execution & Security Attributes

* Elevated Privileges (SUID): Analyze how specific system executables run with owner privileges to understand the security implications of user ID switching.
* Restricted Deletion (Sticky Bit): Implement a public "dropbox" directory where any user can create and modify files, but only the specific owner of a file can delete it.
* Lock Configuration Profiles: Set immutable file attributes on core security configuration files to prevent even the root user from modifying them accidentally.
